{# Re-pricing is a GET so the estimate is always the server's answer, not the browser's arithmetic. A client-side total would be a second opinion about cost, and the whole point of this screen is that there is only one. #} {# `id` so the per-shot prompt and model fields below can join this form with `form="repricer"` while living inside the step cards they belong to. Nesting them here instead would put the plan's controls somewhere other than the plan. #} {# Live re-pricing, and no button. Every control here changes what a run costs, and a screen that only tells you after you ask is a screen people stop asking. The request is still a GET to this same handler, so the estimate remains the server's answer and there is no second implementation of the arithmetic — htmx swaps the changed regions of the response in rather than repainting the document. `from:#plan-body` rather than this form, because half the controls are not inside it. The per-shot prompt, model, length and face fields live in the step cards they describe and join the form by `form="repricer"` — which makes them part of its data but not part of its subtree, so their events never reach it. `#plan-body` contains every one of them, and `change`/`input` both bubble, so delegating there is the only listener that cannot miss a field. The previous `from:(#repricer textarea, #repricer input[type=text], …)` missed all of them, and `input[type=text]` additionally matches nothing with no `type` attribute — which is how the voice-over line is written, and every per-shot model box. `submit` is listed because naming any trigger replaces the default one a form has. Without it, pressing Enter in a field — or a Re-price button, when there was one — fell through to the browser's own GET and navigated: the whole document reloaded, and from the layer that meant being thrown out of it onto a full page. htmx cancels the submit it handles. Debounce on `input`, immediate on `change`. A tick, a radio or a picked option is a finished decision; a prompt being typed is not. `hx-sync` aborts a re-price still in flight when the next one starts, so a slow early response cannot land after a fast later one and put stale text back in the box you are typing in. Everything that survives a swap has an `id`: htmx restores focus and the caret to the element with the same id after replacing a region, and without one, the field being edited comes back scrolled to the top and deselected. That, more than anything, is what made live re-pricing feel like a page reload. `#plan-stats` rides along out-of-band because the estimate lives in the pagebar, which is deliberately outside the scrolling area: the number that decides whether to press the button must not be able to scroll away from it. The rail's copy of the figure and the queue button's own state ride along for a harder reason — they sit outside `#plan-body`, so before this they kept the price and the refusal from whichever plan was last loaded, next to the button that spends it. This works unchanged in the layer, which is why there is no second version of it: `hx-select` picks the regions out of whatever comes back, and the overlay is this same body inside a ``. The one exception is the URL. Pushing it is right on a page, where the address is what you are looking at; in a layer the address belongs to the song underneath, and rewriting it would leave the browser pointing at a screen you closed. #}
