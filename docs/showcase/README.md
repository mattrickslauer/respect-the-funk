Fifteen PNGs, 2880×1800 (1440×900 at 2×), in the order the work happens: the public front
door, then registering an artist, building the identity, measuring the song, pricing the
run, and verifying what came out.

Every screen is the real application rendering real records — the artist, the consent, the
measurement at 79.97 BPM, the delivered clips, the manifests. The instance that produced
them ran on the zero-credential path (`storage local · generator genblaze:mock`, no auth,
no mailer), which is why the footer of each console shot says `5 mocked`. The media on
screen is not mocked: those clips were generated by `openai-sora/sora-2` on earlier real
runs and are being read back out of local storage.

## Regenerating them

`capture.py` drives a real browser against a running console. It needs a local instance on
the zero-credential path — no `.env`, so nothing bills and no code is emailed:

```bash
cd app
RK_DEFAULT_TENANT_ID=<tenant> .venv/bin/uvicorn remixkit.main:app --port 8077
```

Then, with `playwright` installed (`pip install playwright && playwright install chromium`):

```bash
python docs/showcase/capture.py
```

Chromium must be the Chrome-for-Testing build Playwright ships; the plain open-source build
has no H.264 decoder, and the delivered clips would screenshot as black rectangles.

The artist, song, and kit ids are read from the environment (`RK_SHOWCASE_ARTIST`,
`RK_SHOWCASE_SONG`, `RK_SHOWCASE_KIT`) so the script points at whatever records the instance
being shot actually has.
