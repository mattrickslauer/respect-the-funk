## Bottom line

| | T0 · Demo | T1 · Pilot | T2 · Platform |
|---|---|---|---|
| **Total infrastructure / mo** | **$0.45** | **$0.72** | **$3.97** |
| ...of which CockroachDB | **$0.00** | **$0.00** | **$0.00** |
| **Idle / mo** (corpus at rest, nobody generating) | **$0.37** | **$0.44** | **$1.27** |
| Image generation / mo — *the actual bill* | $13.20 | $38.72 | $316.80 |
| Infrastructure as % of total spend | 3.3% | 1.8% | **1.2%** |

**Three things that matter:**

1. **There is no cost argument to have.** MEMORY-SPEC §8 was written braced for one — it concedes the branch "reintroduces the tier that decision removed" and declines to restate the idle number until it was checked. It is now checked. CockroachDB Basic starts at $0/month, **scales to zero**, includes **50M Request Units + 10 GiB storage free every month**, and carries the distributed vector index on that plan. This workload fits inside the free allowance at all three tiers. **infra/README.md's "under $1/month idle" survives the branch** at T0 and T1; at T2 it is exceeded — by **Backblaze B2 storage ($0.92), not by the database ($0.00)**.

2. **The memory tier is a rounding error on its own bill, and a lever on the bill that dominates.** At T1 it costs **$0.0066 per finished video** against **$2.07** of generation and likeness judging — **0.32%**. It pays for itself if it removes **0.0075 attempts per approved still**, out of 2.2. This reinforces rather than contradicts [docs/research/07-cost-model](../docs/research/07-cost-model.md): generation is the bill, everything else is noise, and the memory tier is the cheapest possible way to attack the expensive line.

3. **The binding constraint is not price — it is an unpublished number.** CockroachDB does not publish an RU cost for a vector-index scan. So the free allowance is stated here as *headroom*, not as spend: an operation would have to cost **> 9,542 RU** at T1, or **> 1,147 RU** at T2, before the 50M free allowance breaks. T1 has room to spare. **T2 must be measured**, and days 1–2 of MEMORY-SPEC §9 (deleted 2026-08-15; in git history) is where to record it.

## What was measured, not assumed

Counted out of this repository on 2026-07-26. These are the workload's real drivers, and several of them are much smaller than the design discussion implies.

| Measurement | Value | Consequence |
|---|---|---|
| Library clip descriptors | **28** (13 hooks + 15 `nocturnal`) | Matches MEMORY-SPEC §2's corpus statement |
| Embeddable prose per descriptor | **47 tokens mean, 76 p95** | `title` + `logline` + `audio.quote` + `beats[].means` — the part a human reads |
| One `rtf.clip/v1` as JSON | **2,310 bytes** | With a `VECTOR(1024)`, a clip row is ~6.5 KB |
| Payoff stills per edit | **22** | Consistent across all 5 existing edits (22–25) |
| Existing edits | **5** | `california-`, `generated-`, `nate-`, `smart-`, `storytime-test` |
| Reference framings per artist | **5** | Per MEMORY-SPEC §2 |
| Image generation rate | **$0.04/image** | `generate_stills.py` `PRICES_USD`, dated 2026-07 by the repo |

> **The finding hiding in row two.** Embedding is free in practice. At 47 tokens of prose per clip and $0.02/MTok, embedding a **50,000-clip catalogue costs $0.03 — once.** Whatever the argument for or against this tier is, it is not the cost of embedding.

## Free-allowance headroom — the only thing that can make this cost money

**Storage is a non-event.** A clip row is ~6.5 KB (a 2,310-byte descriptor plus a 4 KB `VECTOR(1024)`); an episode row is ~3.6 KB (including a 2 KB `VECTOR(512)`).

| | T0 | T1 | T2 |
|---|---|---|---|
| CockroachDB storage after 12 months of episodes | 0.04 GiB | 0.05 GiB | **0.63 GiB** |
| ...as % of the free 10 GiB | 0.4% | 0.5% | **6.3%** |

Even T2 — fifty thousand clips plus a full year of episodes — uses 6.3% of the free allowance. Bytes stay in B2; the tier holds vectors and rows, exactly as [`memory-branch.pdf`](./memory-branch.pdf) draws it.

⚠️ **Request Units are stated as an inversion rather than guessed.** No RU cost for a vector-index scan is published anywhere. Rather than invent one:

| | T0 | T1 | T2 |
|---|---|---|---|
| Operations / month | 1,750 | 5,240 | 43,600 |
| **RU per operation before the 50M free allowance breaks** | **28,571** | **9,542** | **1,147** |

For scale, CockroachDB documents a simple point read at single-digit RUs. T1 has three orders of magnitude of room. T2 does not have that luxury and **must be measured** — it is also the cheapest possible thing to measure, and day 1–2 of MEMORY-SPEC §9 already provisions the cluster.

## Unit economics

| Per finished video (22 stills) | T0 | T1 | T2 |
|---|---|---|---|
| Image generation + likeness judging | $2.82 | **$2.07** | $1.69 |
| Memory tier — embeddings, vectors, rows | $0.0078 | **$0.0066** | $0.0061 |
| **Memory tier as % of the video** | 0.28% | **0.32%** | 0.36% |
| Cost per approved still | $0.128 | $0.094 | $0.077 |
| **Attempts/still it must remove to break even** | 0.0089 | **0.0075** | 0.0069 |

**The trade, stated plainly.** Memory costs $0.0066 per video. One attempt-per-still of improvement is worth **$0.88**. So the tier pays for itself at **0.0075 attempts removed per still — about 0.34% of the current figure.**

A move from 3.0 → 2.2 attempts saves **$0.70 per video**, or **$140.80/month at T2** — for a tier that bills nothing. That is the entire economic case, and it does not require the improvement to be large. It requires it to be *non-zero*, which is the falsifiable claim MEMORY-SPEC §6 already commits to testing.

> **This does not overturn docs/research/07-cost-model — it confirms it.** Generation is ~93% of the bill there and 99% here. The memory tier does not add a meaningful line. It is a lever on the line that already dominates, bought in the free column.

## What is not verified

Marked rather than guessed, per the house rule in [docs/research/07-cost-model](../docs/research/07-cost-model.md).

| Item | Status |
|---|---|
| **RU cost of a filtered vector scan** | **UNVERIFIED — the single largest modelling risk.** Not published anywhere. Must be measured on days 1–2. Every headline above is therefore stated as headroom, never as spend. |
| **CockroachDB overage rates** ($0.20/M RU, $0.50/GiB-mo) | **UNVERIFIED — third-party.** The free allowance and scale-to-zero *are* on the vendor pricing page; the rates past it are not, and both vendor pages defer to a quote. They only matter if the free tier breaks. |
| **Fargate Spot discount** (modelled 70% off on-demand) | **UNVERIFIED** — Spot rates are dynamic and absent from the Price List API by design. At 5.0 hr/month this cannot move the total. |
| **CloudWatch** ($0.15/mo) | **UNVERIFIED placeholder** — carried from infra/README.md's "~cents". |
| **Attempts per approved still** | **ASSUMPTION at every tier.** The one number that would change the conclusion, and the one this repo cannot currently produce. |
| **Face embedding model** | **OPEN DESIGN DECISION** (MEMORY-SPEC §10.3). Priced as Titan Image Embeddings at $0.00006/image, which would give Q3 a metric vector rather than the vision model's judgement — a real change to `check_likeness.py`, not a refactor. |
| Gemini 2.5 Flash token rates (likeness judging) | Carried from docs/research/07-cost-model, verified 2026-07-15. |

## Reproducing this

```bash
brew install weasyprint
python3 workload.py          # -> memory-workload.pdf + memory-workload.csv + stdout tables
```

Every number in this file, in the PDF and in the CSV comes from the constants block at the top of [`workload.py`](./workload.py) — the same reason [`diagram.py`](./diagram.py) generates its pictures rather than having them drawn. Changing a rate changes all three, and the stdout table is there to be diffed when one does.
