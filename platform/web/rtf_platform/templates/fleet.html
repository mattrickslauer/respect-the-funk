The fleet

Ten agents, one backbone. None of them calls another — each reads shared memory, acts, writes the result back, and that write wakes the next one. This page renders a specification, not a status board. The pill on every row says whether the thing is running or only written down, and today most of it is only written down.

An agent is three layers contract design §2

Each layer is pure with respect to a different thing. That is the whole modularity claim: an adapter is testable offline, a handler is testable with no database at all, and the runtime is written exactly once for every agent below.

A handler never writes to the database. It returns the facts, metrics, new work and state changes it wants, and the runtime applies all of them in one transaction — so the boundary that stops a crash from double-sending is written once rather than remembered by every agent.

The feedback ladder contract design §9

The fleet sends emails and wants the track to perform. Stream count is the goal and the worst thing to train on — confounded by playlist adds, algorithmic push, seasonality and our own channels firing at once. So the fast rungs train the loop and the slow one only audits it.
